# HANDOFF — CHIP-8 emulator (Virdant)

## What this is

A CHIP-8 computer targeting the `virt::VirtVga` virtual board (50 MHz clock,
UART, SPI flash, VGA RGB444 + syncs). Program is loaded from the simulated
16 MiB SPI flash, executed by a hardware CHIP-8 core, and rendered to the
VGA monitor at 640x480@60. Keypad input decodes UART keystrokes
(`input::KeyDecoder`); sound is stubbed behind a socket (the VirtVga board
has no audio pins).

## Fixed this session (in order)

0. **Real-game bring-up: memories zero-initialized.** Downloaded
   archive games (roms/games/) drew over a noise screen: real games
   don't 00E0 at boot and assume zeroed RAM, but the simulator starts
   uninitialized memory words at random garbage (all our test ROMs
   cleared first, masking it). `initial` is unsupported on memories;
   used `@image_inline` zero images on `data_registers`/`call_stack`
   and `@image("images/frame_buffer_zero.image")` on `frame_buffer`
   (one byte per Word[1] element). Snake title now reconstructs
   cleanly; full battery re-passed (box 12/12, shift 8/8, beep 5/5,
   fx0a 11/11, mem 10/10 — one mem sweep run hit a non-reproducible
   early exit-0 at 5.5M cycles, a rerun to the 6.2M limit passed;
   suspect /tmp-tmpfs RAM pressure from giant VCDs).
   Snake specifics: attract mode runs ~143M cycles (~21 wall minutes)
   before its FX0A; plays with W/A/S/D; see TODO.md for the
   playability/speed follow-up.

1. **Simulator workarounds removed after upstream fixes** (vir v0.4.0,
   `aa357f6`):
   - Bare `dontcare` accepted (upstream `aa357f6`): reverted both
     `else => 0w8` sites in `chip8.vir` to `else => dontcare`.
   - Two-phase memory commit (upstream `b6d3dde`): every memory write
     site is now sampled once per edge against pre-edge values and the
     write is staged and applied together with the register transfers.
     This fixes both artifacts the skids worked around, so **both skid
     buffers were removed**: `frame_buffer` draws directly from
     `draw_new_pixel`, and FX0A commits `Vx := zext(waitkey_key)`
     directly at the WaitKey→Fetch edge. The `call_stack_write_*` wire
     indirection (bug3 workaround) was also removed — `call_stack`
     reads `cpu_state`/`stack_pointer`/`pc` directly again.
   - Verified by the full battery: box (12/12), shift (8/8), beep
     (5/5), fx0a (11/11), mem (10/10) — all ALL CHECKS PASSED.
   - `tools/check_vcd_io.py` fx0a commit subcheck rewritten: it used to
     watch the removed `waitkey_wb_en`/`waitkey_wb_data` skid signals;
     it now records the (cycle, reg_x, waitkey_key) triple at each
     WaitKey→Fetch edge transition and requires exactly one commit of
     V2 := 5.
   - `roms/test_mem.flash` regenerated by `tools/make_test_mem.py` with
     a **success-path 2NNN/00EE roundtrip** (`oksub` at 0x264 draws the
     ok marker, sets V8 = 0x88 and returns; caller checks V8 with
     `3888`). Previously the call_stack was only written on the fail
     path, which no passing run ever took. Note: `6XNN`'s register is
     the low nibble of the high byte — `6888` is `V8 := 0x88`, not V9
     (first run of the extended ROM failed on exactly that).
   - The mem checker now needs `--cycles 6200000` so a complete frame
     follows the last draw (~5.06M cycles of program + loader).

1. **SPI command misalignment** (`flash_loader.vir`): gated the command
   shift with `cmd_bits != 0` (first shift skipped so bit31 is sampled at
   the flash's first active rising edge) and moved the CmdAddr→ReadData
   transition to `cmd_bits == 32`. Loader now delivers byte-exact data.
2. **frame_buffer write re-fire hazard** (`chip8.vir`): the Draw-cycle
   write data (`draw_new_pixel`) reads the same memory being written.
   The simulator's memory-write driver re-evaluates when its inputs
   change: the first drawn pixel was poisoned by its own readback and
   the last pixel's write was skipped at the Draw→WriteVf edge. Found by
   reconstructing the framebuffer from the VGA scan in the VCD (first +
   last pixel of the box read back 0). Fix: **skid buffer**
   (`draw_wb_en/addr/data` regs) — the write commits on the following
   cycle with cycle-stable inputs. A single DXYN never revisits a pixel,
   so the one-cycle delay is semantically exact.
3. **8XY7 never reached WriteVf** (`chip8.vir`): `execute_next_state`
   routed 4/5/6/e but not 7, so 8XY7's VF (no-borrow) was never
   committed. Added `with 0x7 => #WriteVf`.
4. **FX0A Vx commit dropped** (`chip8.vir`): same exit-edge artifact as
   (2) — the Vx commit coincided with the WaitKey→Fetch edge and Vx kept
   garbage (observed draw at y=27 instead of key=5). Fix: **second skid**
   (`waitkey_wb_en/data`), commit fires during the following Fetch cycle.
5. **FX0A run completed (no OOM)**: the 2.6M-cycle OOM was fixed by
   running **5.2M cycles** with `--trace` (a full 2 frames after the
   last draw: 5.2M cycles = 52.0ms; the 'W' press at ~10s wall time
   lands in-cycle at t=1.734ms, release at t=2.674ms, so the run is
   long enough). Peak RSS was fine (no OOM). Exit 124 (the --cycles
   limit). **The checker now runs to completion and reports the
   failures above.**

## Learnings about the Virdant simulator (important)

- **Memory writes use proper pre-edge (NBA) semantics** as of upstream
  `b6d3dde` (two-phase commit: write sites evaluated once per edge
  against pre-edge values, staged, applied with the register
  transfers). The earlier symptoms (self-RMW "poisoning", exit-edge
  dropped writes, declaration-order dependence) all had ONE root cause:
  the old simulator sampled write sites against the live (partly
  post-edge) state at each memory's own commit — see
  `virdant/bug3/REPORT.md` for the mechanism analysis. The earlier
  "write driver re-fires when its inputs change" wording was wrong.
  All skid buffers and wire indirection in this project were removed
  and re-verified; direct writes (including same-cycle async-read RMW
  like the framebuffer draw) are now exact.
- **Register initial values are random garbage** (not 0) until `initial`
  commits; memories too. ROMs must 00E0-clear before framebuffer checks.
- `advance <µs>` in poke scripts moves sim time but **does not clock the
  design**; only `tick` does. Poke has no loops — generate scripts.
- Poke can read hierarchical paths (`print core.keypad.key`) and assert.
- VGA geometry: 800×525 pixels at 25 MHz (÷2) = **840,000 board cycles
  per frame**; vsync pulses at cycles 784k + 840k·k. A framebuffer
  reconstruction check needs ≥2 complete frames *after* the last draw
  (≥3.4M cycles), which OOMs with --trace; use a frame that starts after
  the last draw instead (2.6M cycles works for late draws).
- VCD notes: identifiers can be multi-char (`"2`); one board cycle spans
  two `#` timestamps (20000 ps); a "stable" timestamp may contain
  post-commit delta artifacts, so sample registered signals at
  end-of-timestamp and verify memory contents end-to-end, not via
  combinational write-path signals.
- **VCD trace analysis: `grep`-based extraction is the way to go** —
  the VCD is 382 MB for 5.2M cycles; a full parse in Python is slow.
  Use `grep -n 'b[0-9]* R$'` to find the cpu_state transitions and
  `sed -n` around them to find the surrounding timestamps. The
  `--cycles` limit is 124; exit 137 = OOM kill.

## input::KeyDecoder

Replaces `KeyStub` (deleted). 115200 8N1, LSB-first, 434-cycle bit period
(434.03 exact; error < 0.25 cycle over 8 bits). Start bit trusted only
after 100 idle-high cycles (glitch gate). Keystrokes are ASCII on the
classic CHIP-8 layout (both cases): `1234/QWER/ASDF/ZXCV` →
`123C/456D/789E/A0BF`. UART cannot signal release, so: a key's character
presses it, the same character again releases it, a different key's
character moves the press; at most one key held. Verified by
`test/keydec.poke`.

## Layout

```
virdant.toml        [prog] top = "top::Top"
src/
  top.vir           Top for virt::VirtVga: loader + core + VGA + decoder + sound stub
  chip8.vir         CpuState enum, Keypad/Audio sockets, Chip8 core (+ two write skids)
  flash_loader.vir  SPI 0x03 READ loader (fixed command framing)
  vga.vir           640x480@60 sync generator, scan -> CHIP-8 x/y decode
  sound.vir         SoundStub (audio socket server; VirtVga has no audio pins)
  input.vir         KeyDecoder (UART 115200 -> keypad socket)
  keydec_tb.vir     poke testbench top for the decoder (test:: src::KeyDecTb)
test/
  keydec.poke       generated bit-bang UART testbench (~22k lines)
tools/
  check_vcd.py      main bring-up checker (incl. framebuffer reconstruction)
  check_vcd_shift.py shift/8XY7 checker
  check_vcd_io.py   fx0a + beep + mem checkers (mode argument)
  fx0a_keys.py      deterministic fx0a keystroke stimulus (redirect to stdin)
  make_test_mem.py  assembles roms/test_mem.{ch8,flash}
  make_flash.py     converts any .ch8 game into a 4 KiB .flash image
                    (classic font baked at 0x000, program at 0x200)
roms/               test_box / test_shift / test_fx0a / test_beep /
                    test_mem (.ch8 + .flash), games/ (archive games +
                    README.md with controls)
images/             frame_buffer_zero.image (2048 zero bytes, one per
                    Word[1] element — the @image zero-init of the
                    framebuffer)
```

## How to run

```
cd /tmp/tmp.gbUN1DPQiv/chip8
vir check
vir run --flash roms/test_box.flash --cycles 2600000 --trace /tmp/box.vcd --fps-no-cap
python3 tools/check_vcd.py /tmp/box.vcd roms/test_box.flash

vir run --flash roms/test_shift.flash --cycles 2200000 --trace /tmp/shift.vcd --fps-no-cap
python3 tools/check_vcd_shift.py /tmp/shift.vcd roms/test_shift.flash

vir run --flash roms/test_beep.flash --cycles 1300000 --trace /tmp/beep.vcd --fps-no-cap
python3 tools/check_vcd_io.py beep /tmp/beep.vcd roms/test_beep.flash

# fx0a: keystrokes MUST come from the deterministic stimulus generator
# (a wall-clock sleep pipe is nondeterministic — the press landed
# before WaitKey even began). Run 5.2M cycles to complete the checker
# (exit 124 = cycles limit, expected):
python3 tools/fx0a_keys.py > /tmp/fx0a_keys.bin
vir run --flash roms/test_fx0a.flash --cycles 5200000 --trace /tmp/fx0a.vcd \
  --fps-no-cap < /tmp/fx0a_keys.bin
python3 tools/check_vcd_io.py fx0a /tmp/fx0a.vcd roms/test_fx0a.flash

# mem: FX33/FX55/FX65 + success-path 2NNN/00EE roundtrip (regenerate
# the ROM with tools/make_test_mem.py if it changes). 6.2M cycles so a
# complete frame follows the last draw:
vir run --flash roms/test_mem.flash --cycles 6200000 --trace /tmp/mem.vcd --fps-no-cap
python3 tools/check_vcd_io.py mem /tmp/mem.vcd roms/test_mem.flash

# games (see roms/games/README.md; type into the terminal to play):
python3 tools/make_flash.py roms/games/snake.ch8   # if regenerating
vir run --flash roms/games/snake.flash             # snake: W/A/S/D

# decoder unit test (no loop construct — file is generated, ~22k lines):
vir poke --top Top test/keydec.poke
```

`vir run` exits 124 on `--cycles`. Exit 137 = OOM kill with long --trace
runs; 5.2M cycles is fine (≈382 MB VCD). The full checker parse of that
VCD is slow (~10 min) in Python — the `grep`-based extraction in
`tools/check_vcd_io.py` is the way to go for future checkers.
